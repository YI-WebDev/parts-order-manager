# F06 請求書の編集

明細表と、出力と同じ見た目の Excelプレビューを並べて請求書を編集し、自動で保存する。

- 画面: `InvoicePanel.tsx`（明細表・チェック・明細最終行の検索欄・出力前の確認）、`SheetPreview.tsx`（Excelプレビューと帳票上部の入力）、`editor-store.ts`（自動保存）、`useInvoiceWorkspace.ts`（画面の移動・確認・出力の呼び出し）
- IPC: `documents:open`・`documents:duplicate`・`documents:add-line`・`documents:save`
- 実装: `src-tauri/core/src/documents.rs`（`DocumentEditor`）

## 画面の構成

| 部分 | 内容 |
|---|---|
| 上 | 「← 請求書一覧」、管理用タイトル（帳票には出さない）、エラー・出力の結果 |
| 左 | 明細表（#・品名・型式・メーカー・数量・備考・チェック・削除）、明細の行数「N / 47行」、「材料を選んでまとめて追加」、明細最終行の検索欄（[F03](F03-material-search.md)） |
| 右 | Excelプレビュー（[F07](F07-cell-format.md) のツールバー、名前ボックス、表示倍率30〜200%・幅に合わせる、「入力欄に色を付ける」）。左右の幅の割合は25〜70%で、境目のドラッグか ←→ で変える |
| 下 | 保存の状態、保存版、「保存を再試行」（失敗時）、「出力前の確認 N件」／「出力の準備ができています」、「印刷プレビュー・PDF」、「Excelへ出力」 |

## 明細と帳票上部

| ID | 要件 |
|---|---|
| REQ-EDT-001 | 明細の品名・型式・メーカー・数量・備考と、帳票上部の5欄、管理用タイトルは、各10,000文字までの自由な文字。数量も文字のまま扱う |
| REQ-EDT-002 | 帳票上部（上部欄 C2・ヘッダー欄 A4/B4/C4・納期 E4）は、Excelプレビューの該当セルに直接入力する。明細のセルをプレビューで選ぶと、明細表の該当の欄へフォーカスを移す。明細表の欄にフォーカスすると、プレビューの該当のセルを選ぶ |
| REQ-EDT-003 | 保存するとき、明細の5項目と帳票上部の5欄の前後の空白（全角・半角）を除く。管理用タイトルは除かない。入力欄には入力したままの文字が残り、プレビューは除いた形で描く |
| REQ-EDT-004 | 明細はドラッグ（行の番号の部分）か Alt+↑↓ で並べ替える。並べ替えた後もフォーカスは同じ明細のつまみに残る |
| REQ-EDT-005 | 明細の削除は「この明細を削除しますか？」で確かめてから行う。明細の追加・削除・並べ替えは元に戻せない |
| REQ-EDT-006 | 数量の欄で Enter を押すと、次の明細の数量へ移る（最後の明細なら明細最終行の検索欄へ） |
| REQ-EDT-007 | 1つの請求書の明細は500行まで。帳票に入るのは47行までで、48行目以降があると行数の表示を警告の色にし、プレビューに「明細が47行をN行超えています。48行目以降は帳票に入りません。」を出す |
| REQ-EDT-008 | チェックは「材料のみ（●）」「伝票のみ（○）」「材料・伝票とも納品（⦿）」の3択で、任意。選んでいる記号をもう一度押すと未選択に戻る。←→↑↓でフォーカスを移し、Space・Enter で選ぶ。状態と記号がそろっていない明細（記号未確定など）は、どれも選んでいないように見せ、行を警告の色にする |

## 出力前の確認

| ID | 要件 |
|---|---|
| REQ-EDT-101 | 下書きから、出力を止める理由を画面で先に求めて件数を示す: 記号未確定（「明細N「品名」のチェック記号が未確定（…「⦿」を選び直してください）」）、状態と記号の不一致、47行の超過、納期の形式（実在する日付を `YYYY-MM-DD` または `YYYY/M/D`。前後の空白を除いた値で判定）、帳票形式が `excel-v1` でない。規則と文言は `shared/export-issues.ts` の1か所（`InvoicePanel`・`SheetPreview` が使う）で、本体の `exports::blocking_issues` と同じ（[F08](F08-excel-export.md) の REQ-XLS-002） |
| REQ-EDT-102 | 本体が出力・印刷プレビューを止めた（`blocked`）ときは、本体の理由を画面の理由に重ねて（同じ項目は1つにして）一覧で示し、止めた操作（Excel出力・印刷プレビュー）を見出しに出す。編集したら本体の理由は外し、画面の判定に戻す |
| REQ-EDT-103 | 一覧の項目を押すと、該当の明細へスクロールしてチェックの欄へフォーカスし、行を一時的に強調する（納期なら納期のセルへ）。Esc で一覧を閉じる |
| REQ-EDT-104 | 出力前の確認は止める理由だけを数える。チェックを選んでいない明細は数えない（チェック欄を空欄で出力する） |

## 自動保存

### 状態

画面の保存の状態（`EditorState`）と表示:

| 状態 | 表示 | 意味 |
|---|---|---|
| `idle` | 未保存 | 編集していない（破棄した新規など） |
| `waiting` | 未保存（自動保存待機中） | 未保存の変更があり、保存を待っている |
| `saving` | 保存中… | 保存の要求を送っている |
| `saved` | 保存済み | 画面の下書きと保存版が同じ |
| `error` | 保存失敗 | 本体がエラーを返した、または保存の結果が分からない |
| （変換中） | 変換確定を待っています | 編集画面の欄で日本語を変換している。保存しない |

内部の状態: `dirty`（未保存の変更あり）、`generation`（編集の通し番号）、`requestNumber`（保存の要求番号）、`pending`（送った要求）、`unknownOutcome`（結果の分からない要求あり）、`paused`（画面の処理中）。

### 遷移

| 今 | 出来事 | 次 | 決まり |
|---|---|---|---|
| — | 既存の請求書を開く | `saved` | 保存版は1以上 |
| — | 新規・複製を開く | `waiting`（`dirty`） | すぐに自動保存の対象になる（保存版0。`audit/` の E-09） |
| `saved`・`waiting` | 編集する | `waiting` | 内容が変わらない編集は無視する |
| `waiting` | 最後の編集から0.5秒（未保存の最初の編集から2秒を超えない） | `saving` | 変換中・画面の処理中・`error` の間は待たない |
| `saving` | 成功の応答（受領書が要求と一致） | `saved`／`waiting` | 送った後に編集していれば続けて保存する |
| `saving` | エラーの応答 | `error` | 自動では再試行しない。「保存を再試行」・Ctrl+S で再送する |
| `saving` | 応答なし・受領書の不一致 | `error`（`unknownOutcome`） | 「保存結果が不明です。入力を保持しています。再試行で同じ要求を確認してください。」。再試行は同じ要求（同じ要求番号・内容）を送る |
| `error`（`unknownOutcome`） | 別の請求書を開く・閉じる | （変えない） | 結果が分かるまで請求書を切り替えない |
| 任意 | 変換を始める | （変換中） | 自動保存のタイマーを止める。変換が終わったら再開する |

### 本体の保存の規則（`documents:save`）

| ID | 要件 |
|---|---|
| REQ-EDT-201 | 保存は、今の編集セッションに対してだけ受け付ける（違えば `CONFLICT`「編集セッションが変わりました。…」） |
| REQ-EDT-202 | 要求番号は1から1ずつ増やし、編集の通し番号（`generation`）は前回より大きく、期待する保存版はセッションの保存版と同じであること（違えば `CONFLICT`「保存要求の順序または版が一致しません。…」）。直前と同じ要求番号・同じ内容の再送には、同じ受領書を返す（二重に保存しない） |
| REQ-EDT-203 | 明細の ID は、このセッションで開いた・追加した明細のもので、重複しないこと。出典（材料 ID・原記録 ID）・`observedMark`・記号の規則は変えられない（違えば `VALIDATION`「明細IDまたは出典が一致しません。」） |
| REQ-EDT-204 | チェックを変えた明細は、状態と記号が対応していること（未選択→`unresolved`、材料のみ→`filled_circle`、伝票のみ→`open_circle`、共に納品→`both_mark`）。変えていない明細は、記号未確定のままでも保存できる |
| REQ-EDT-205 | 帳票形式は変えられない。明細は500行まで、要求は1 MiB まで |
| REQ-EDT-206 | 新規（保存版0）の最初の保存で請求書を作り、保存版1にする。複製なら複製元を記録する。以後は保存版を1ずつ上げる（楽観ロック） |
| REQ-EDT-207 | 500行または1 MiB を超える請求書は開かない（「帳票は編集画面の上限（500行・1MiB）を超えています。元の保存内容は保持されています。」） |

## 画面の移動・未保存の確認

| ID | 要件 |
|---|---|
| REQ-EDT-301 | 未保存の変更があるまま一覧・ほかのタブへ移る、別の請求書を開く、新規を作る、バックアップ・復元を始める、ウィンドウを閉じるときは「未保存の変更があります」で「戻る」「保存して続ける」「未保存分を破棄」を選ばせる |
| REQ-EDT-302 | 編集画面の欄で変換中は、移動せず「日本語の変換を確定してから操作してください。」を出す |
| REQ-EDT-303 | 「未保存分を破棄」は、送っている保存の結果を待ち、結果が分からない要求があれば同じ要求で確かめてから、最後に保存した下書きへ戻す |
| REQ-EDT-304 | Ctrl+S（請求書を開いているとき）で今すぐ保存する |

## 受け入れ基準

| ID | 前提 | 操作 | 結果 |
|---|---|---|---|
| AC-EDT-001 | 既存の請求書 | 品名を変えて2秒待つ | 「保存済み」になり、保存版が1上がる |
| AC-EDT-002 | 保存の応答が届かない | 「保存を再試行」 | 同じ要求を送り、二重に保存されない（保存版は1だけ上がる） |
| AC-EDT-003 | 保存がエラーになった | 何もしない | 自動では再送しない。表示は「保存失敗」のまま |
| AC-EDT-004 | 未保存の変更がある | 「← 請求書一覧」 | 確認が出る。「戻る」で編集に残り、入力はそのまま |
| AC-EDT-005 | 品名の欄で変換中 | 「Excelへ出力」・タブの移動 | どちらも行わず、変換の確定を求める。保存もしない |
| AC-EDT-006 | 記号未確定（`both`・`unresolved`）の明細 | ⦿ を押して保存する | 保存でき、出力前の確認から消える |
| AC-EDT-007 | 明細が48行 | 画面を見る | 「48 / 47行」が警告の色になり、出力前の確認に47行の超過が出る |
| AC-EDT-008 | 納期に「 2026/10/31 」（前後に空白） | 保存して出力前の確認を見る | 納期の形式の項目は出ない。帳票には「10月31日」と出る |
| AC-EDT-009（想定外の操作） | 開いていない編集セッションの ID | `documents:save` を直接呼ぶ | `CONFLICT` で拒否される |

## 未確定・既知の問題

`audit/` の未対応の指摘: E-05（端の行の Alt+↑↓ でフォーカスが引き戻される）、E-06（明細の削除の後にフォーカスが失われる）、E-08（保存できたのに開けない 1MiB の境界）、E-09（新規・複製を開いただけで保存される）、E-11（終了確認の受け取りを付け直している）。

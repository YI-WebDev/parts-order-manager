# F08 Excel出力

保存版の請求書を、見本と同じ帳票（[05-sheet-layout.md](../05-sheet-layout.md)）の `.xlsx` に出力する。

- 画面: 編集画面の「Excelへ出力」（`InvoicePanel.tsx`・`useInvoiceWorkspace.ts` `exportExcel`）
- IPC: `documents:export-excel`
- 実装: `src-tauri/core/src/api.rs`（`export_excel`・`export_steps`）、`exports/mod.rs`（ブックの組立て・検証）、`exports/files.rs`（出力先の検査・確定）

## 流れ

1. 画面の事前判定（[F06](F06-invoice-editor.md) の出力前の確認）に項目があれば、出力せずに保存して一覧を開く。
2. 変換中なら止める。未保存の変更を保存し終える（保存できなければ「保存を完了できないため出力していません。…」）。保存版が1以上で未保存の変更がないことを確かめる。
3. 本体が保存版を読み、止める理由があれば `blocked` を返す（画面は一覧で示す）。
4. ブックを組み立てる（文字・容量の制約に反すれば `VALIDATION`）。
5. 保存のダイアログ（既定は「ドキュメント」の `請求書.xlsx`）。取り消せば `cancelled`。
6. 出力先を検査する。既存のファイルなら、このアプリの出力かを確かめてから上書きを確認する（「戻る」「上書きする」）。
7. 選んだ後に出力先が変わっていないこと、保存版と出力の内容が変わっていないことを確かめてから、一時ファイル経由で確定する。
8. 出力の記録（請求書 ID・保存版・日時）を `ui-meta.json` に残し、`ok` を返す。

## 要件

| ID | 要件 |
|---|---|
| REQ-XLS-001 | 出力するのは、指定した請求書の指定した保存版。本体の保存版と違えば「保存版が変わりました。最新の保存を確認して出力し直してください。」（`CONFLICT`）。請求書がなければ `NOT_FOUND` |
| REQ-XLS-002 | 止める理由: 帳票形式が `excel-v1` でない（`templateVersion`）、納期の形式（`E4`）、明細が47行を超える（`lines`）、記号未確定・状態と記号の不一致（`lines.<番号>.mark`）。チェックを選んでいない明細は止めず、チェック欄を空欄で出す。この規則と文言は本体の `exports::blocking_issues`（Excel出力・印刷・一覧の件数）と画面の `shared/export-issues.ts` に1つずつあり、文言は同じ（「この帳票形式のExcel出力には対応していません」「納期の形式（実在する日付を YYYY-MM-DD または YYYY/M/D）」「明細が47行をN行超えています（出力方法は未確定）」「明細N「品名」のチェック記号が未確定（材料・伝票とも。「⦿」を選び直してください）」「明細N「品名」のチェック状態と記号が一致していません」）。納期は前後の空白を除いた値で判定し、帳票に置く値も前後の空白を除いた形（REQ-XLS-102） |
| REQ-XLS-003 | ブックは6つの部品（`[Content_Types].xml`・`_rels/.rels`・`xl/workbook.xml`・`xl/_rels/workbook.xml.rels`・`xl/styles.xml`・`xl/worksheets/sheet1.xml`）だけで作る。シート名は「請求書」、印刷範囲は A1:G56、文字はインライン文字列、数量は文字列（「文字列として保存された数値」の警告を出さない設定） |
| REQ-XLS-004 | 1セルの文字は 32,767（UTF-16）・改行253個まで、XML の合計は2 MiB まで。制御文字（タブ・改行・復帰を除く）・U+FFFE・U+FFFF を含む文字は出力しない（「出力できない文字・文字量または帳票形式です。…」） |
| REQ-XLS-005 | 出力先は拡張子 `.xlsx`、ローカルドライブの絶対パスで、保存場所・アプリのフォルダーの中でないこと。Windows で使えない文字・予約名・末尾の点や空白、取込元の材料Excelの特定の名前（`a 部品発注書 2026-latest.xlsx`）は選べない（「出力先を確認してください。元Excel・内部データ・リンク先への上書きはできません。別のファイル名を選んでください。」） |
| REQ-XLS-006 | 既存のファイルへの上書きは、そのファイルがこのアプリの出力（6部品の構成、シート以外の部品が一致、`styles.xml` が書式の記録から作り直せる、8 MiB 以下）のときだけ。それ以外は別の名前を求める |
| REQ-XLS-007 | 新規保存は、同じフォルダーの一時ファイルに書いてから、同名のファイルがない場合に限って確定する（Windows は置換なしの移動、ほかはハードリンク）。確定の直前に、保存版と出力の内容が準備したときと同じかを確かめる（違えば「保存版または出力条件が変わりました。出力をやり直してください。」） |
| REQ-XLS-008 | 一時ファイルを消せなかったときは、確定済みなら `ok` に、未確定ならエラーに一時ファイルの名前（`cleanup.temporaryName`）を付け、消し方を画面に示す |
| REQ-XLS-009 | Excel出力は同時に1つだけ（「Excel出力の終了を待ってください。」（`BUSY`）） |
| REQ-XLS-010 | 出力に成功したら「保存版 N をExcelへ出力しました。」を知らせ、請求書一覧で「出力済み」にする。取り消したら「Excel出力を取り消しました。請求書の保存内容は保持しています。」 |
| REQ-XLS-011 | 応答が届かなかったときは「出力結果を確認できませんでした。保存先を確認してから再試行してください。請求書の保存内容は保持しています。」 |

## 受け入れ基準

| ID | 前提 | 操作 | 結果 |
|---|---|---|---|
| AC-XLS-001 | 明細3行、1行はチェック未選択 | Excelへ出力 | 出力でき、未選択の行のチェック欄は空欄 |
| AC-XLS-002 | 記号未確定の明細 | Excelへ出力 | 保存だけして出力せず、出力前の確認の一覧で該当の明細を示す |
| AC-XLS-003 | このアプリで出力した xlsx | 同じ名前に出力し「上書きする」 | 置き換わる |
| AC-XLS-004 | 別のアプリで作った xlsx | 同じ名前に出力 | 上書きせず、別の名前を求める |
| AC-XLS-005 | 保存のダイアログを開いている間に、別の経路で保存版が変わった | 保存先を決める | 確定せず「保存版または出力条件が変わりました。…」 |
| AC-XLS-006 | 確定の後に一時ファイルの削除に失敗する | 出力 | 出力は確定済みと示し、残った一時ファイルの名前と消し方を出す |
| AC-XLS-007 | 出力したファイル | Excel・LibreOffice で開く | A4縦1ページに収まり、数式はない（`pnpm test:office`） |

## 未確定・既知の問題

- 47行を超える明細の出力方法（続紙など）は業務ルールが未確定のため、出力を止める。
- `audit/` の未対応の指摘: O-01（スクロールしていると失敗が見えない）、O-02（原因の欄を示さずに止まる場合）、O-04（UNC の保存先の文言）、O-05（「準備しています…」が残る）、O-06（ZIP でない既存ファイル）、O-08（OneDrive）、O-10（確定中の×）。
- 2026年10月15日（既定の揃えを中央にした版）より前に出力した xlsx には上書きできない（別の名前で出力する）。
- 出力先の検査に、取込元の材料Excelのファイル名を1つだけ直書きしている（[09-tech-debt.md](../09-tech-debt.md) の TD-54）。

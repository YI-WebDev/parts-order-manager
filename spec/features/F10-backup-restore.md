# F10 バックアップ・検査・復元

全データ（DB）を1つのファイル `.pombak` に保存し、検査してから復元する。形式は [04-data-model.md](../04-data-model.md)。

- 画面: 「設定」タブの「バックアップと復元」（`BackupPanel.tsx`）、請求書一覧のバックアップの警告（[F05](F05-invoice-list.md)）
- IPC: `backups:create`・`backups:inspect`・`backups:restore`・`backups:status`
- 実装: `src-tauri/core/src/backups.rs`、`api.rs`（`backup_*`）

## 含めるもの・含めないもの

| 含める | 含めない |
|---|---|
| DB の全体（材料・カテゴリ・請求書・明細・書式・取込の原記録・判断履歴・作成の受領記録・設定） | 元の材料Excel、出力した Excel・PDF、`ui-meta.json`（最終バックアップ日時・出力の記録）、フォント・プリンター・Windows の設定 |

## 要件

| ID | 要件 |
|---|---|
| REQ-BAK-001 | 「今すぐ保存」で、保存のダイアログ（既定は「ドキュメント」の `発注書管理-<UTCの日付>.pombak`）を出し、新しい名前にだけ保存する（既存のファイルは上書きしない: 「バックアップは上書きしません。新しいファイル名で保存してください。」） |
| REQ-BAK-002 | 保存の間は、ほかの DB を使う要求を受け付けない（`DatabaseGate` を凍結）。ほかの処理・ファイル選択・印刷プレビューが動いていればバックアップを始めない（「処理中の要求があります。…」） |
| REQ-BAK-003 | DB はオンラインバックアップで複製し、複製を検証してから目録を付けて書く（128 MiB まで）。保存は出力と同じく一時ファイル経由で確定する |
| REQ-BAK-004 | 保存に成功したら最終バックアップ日時を記録し、「バックアップを保存しました。暗号化されていないため安全な場所で保管してください。」を出す |
| REQ-BAK-005 | 「ファイルを選んで検査」で選んだ `.pombak` を、形式・版・チェックサム・DB の構造（REQ-BAK-101・102）で検査し、作成日時（UTC）・材料の件数（削除した材料を除く）・請求書の件数を示す。検査だけでは何も変えない |
| REQ-BAK-006 | 検査の間にファイルが変わったら（大きさ・更新日時・ファイルの実体）、受け付けない |
| REQ-BAK-007 | 復元できるのは、この画面で直前に検査したバックアップだけ（違えば「この画面でバックアップを選び直し、検査してください。」）。復元の前に「現在の全データを退避し、検査したバックアップへ置き換えます。」を確かめる（既定は「戻る」） |
| REQ-BAK-008 | 復元は、切替記録（`restore-journal.json`）を書いてから、DB を閉じ、今の DB を `database-before-<id>` へ退避し、検査済みの候補を `database` に置き、開けることを確かめ、確定の記録を書く。途中で止まったら、次の起動で確定するか元の DB へ戻す |
| REQ-BAK-009 | 復元の後は、成功・失敗のどちらでも結果を示してアプリを終了する（もう一度起動して確かめる） |
| REQ-BAK-010 | 起動時の回復の結果（「復元済みDBの整合性を確認しました。…」「中断した復元を取り消し、復元前のDB一式へ戻しました。…」）を、設定画面の「復元の回復結果」に出す |
| REQ-BAK-011 | バックアップ・復元の処理は同時に1つだけ（「バックアップ・復元の処理が終わるまでお待ちください。」）。未保存の請求書があれば、始める前に保存か破棄を確かめる |
| REQ-BAK-012 | 設定画面に、最終バックアップ日時（この端末で作ったもの）と経過日数を出す。7日以上・記録なしは注意の表示にする |
| REQ-BAK-013 | 平文であること・移行の範囲・保存先・回復の注意を画面に示す |

## 復元の状態

| 段階（`RestorePoint`） | 途中で止まったときの次の起動 |
|---|---|
| 準備（切替記録を書いた） | 退避がなければ今の DB を検証して、取り消しとして記録する |
| DB を閉じた | 同上 |
| 退避した（`database-before-<id>`） | 退避を `database` へ戻す（途中の `database` があれば `database-interrupted-<id>` へ） |
| 候補を置いた | 同上 |
| 開けることを確かめた | 同上 |
| 確定の記録を書いた（`restore-committed-<id>.json`） | 確定済みの DB を検証して、完了として記録する |

## 受け入れ基準

| ID | 前提 | 操作 | 結果 |
|---|---|---|---|
| AC-BAK-001 | 材料3件・請求書2件 | バックアップを保存し、検査する | 材料3件・請求書2件と示される |
| AC-BAK-002 | 既存の `.pombak` の名前 | その名前で保存する | 上書きせずエラーになる |
| AC-BAK-003 | 検査したバックアップ | 復元し、もう一度起動する | 検査した時点のデータになり、元の DB は `database-before-<id>` に残る |
| AC-BAK-004 | 復元の途中（退避した後）で異常終了する | 起動する | 元の DB に戻り、設定画面に回復の結果が出る |
| AC-BAK-005 | 3版（材料の削除を足す前）のバックアップ | 検査・復元する | 受け付け、復元後の起動で4版へ移行する |
| AC-BAK-006 | 別の版のアプリで作ったバックアップ | 検査する | 「このアプリの版・レイアウト・移行履歴と一致しません。」 |
| AC-BAK-007（想定外の操作） | 印刷プレビューを開いている | バックアップを保存する | 始まらない |

## 未確定・既知の問題

`audit/` の未対応の指摘: B-01（現在の DB が検査に通らないときの理由が出ない）、B-02（作業用の DB の複製が保存場所に残り続ける）、B-03（中断した復元の取り消しが最初の画面に出ない）、B-04（古いバックアップへ復元すると未出力の請求書が「出力済み」と表示される）、B-05（アプリを更新すると以前のバックアップが使えなくなるのに警告が出ない。版の完全一致を求めるため）、B-06（DB が壊れると復元にたどり着けない）、B-07（バックアップの受付と「閉じる」が重なると固まる）、B-08（保存先を拒否した理由が汎用の文言）、B-11（既定の名前の日付が UTC）、B-13（既定の保存先が OneDrive に同期されることがある）。

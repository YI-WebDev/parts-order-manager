# F05 請求書一覧

保存済みの請求書をカードで一覧し、開く・新規作成・複製・削除を行う。「請求書」タブの最初の画面。

- 画面: `InvoiceHistory.tsx`（`CardMenu`・`BackupWarning`）、`ConfirmDialog.tsx`（削除の確認）、`document-labels.ts`
- IPC: `documents:list`・`documents:open`・`documents:duplicate`・`documents:delete`、`backups:status`
- 実装: `src-tauri/core/src/documents.rs`（`DocumentEditor::list`・`delete`）

## 要件

| ID | 要件 |
|---|---|
| REQ-LST-001 | 請求書を更新日時の新しい順（同時刻は ID の降順）に20件ずつ表示する。「前の20件」「次の20件」とページ番号を出す |
| REQ-LST-002 | 絞り込みは、管理用タイトルか上部欄（C2）の部分一致（前後の空白を除いた検索語。`%`・`_`・`\` は文字として扱う）。入力から250ミリ秒待って反映し、変換中も入力中の文字で絞る。送るのは先頭の256文字まで |
| REQ-LST-003 | カードには、管理用タイトル（なければ「（タイトルなし）」）、上部欄（なければ「上部欄 未入力」）、明細の行数、保存版、更新日時（月日・時分）、複製した請求書なら「複製」、状態のバッジを出す。開いている請求書には「編集中」を付ける |
| REQ-LST-004 | 状態のバッジ: 明細が0行なら「下書き」、出力前の確認があれば「確認 N件」、最後の Excel出力の保存版が今の保存版と同じなら「出力済み」、それ以外は「出力可」 |
| REQ-LST-005 | 出力前の確認の件数（`issueCount`）は、記号未確定・状態と記号の不一致の明細の数＋明細が47行を超えていれば1＋納期の形式が正しくなければ1＋帳票形式が `excel-v1` でなければ1（Excel出力が止める理由と同じ関数 `exports::blocking_issues` の件数）。納期は前後の空白を除いた値で判定する。チェックを選んでいない明細は数えない |
| REQ-LST-006 | カードのどこを押しても開く。「…」（その他の操作）のメニューから「複製して編集」「削除」を選ぶ |
| REQ-LST-007 | 「新規請求書」（Ctrl+N）で空の請求書を開く。新規・複製は、開いた時点で保存版0の下書きとして自動保存の対象になる（何も入力しなくても保存される。`audit/` の E-09） |
| REQ-LST-008 | 選択は表示中のページの中だけで持つ（ページ・絞り込みを変えると解除）。選んでいる間は、カードをマウスで押すと開かずに選択を切り替える（キーボードの Enter・Space では開く） |
| REQ-LST-009 | 削除は1件ずつ（メニュー）、または選んだものをまとめて（1〜100件）。確認の画面に、タイトル・上部欄・明細の行数・更新日時を並べ、既定のフォーカスは「戻る」。削除は取り消せない |
| REQ-LST-010 | 削除は1つのトランザクションで、明細と書式も一緒に消す。削除した請求書から複製した請求書は残し、複製元の記録だけを外す（内容・版・更新日時は変えない）。出力の記録（`ui-meta.json`）からも消す。材料と、出力済みのファイルは変わらない |
| REQ-LST-011 | 開いている請求書を削除したら、編集の状態も閉じる（本体の編集セッションも閉じる） |
| REQ-LST-012 | 削除した後は、消えたカードをすぐに外し、一覧を読み直してから、消えた位置に来たカードのチェックへフォーカスを移す（カードがなければ「新規請求書」。フォーカスが失われているときだけ）。ページが空になったら前のページへ戻る |
| REQ-LST-013 | 「…」メニューは、開くと最初の項目（↑で開いたら最後の項目）へフォーカスを移し、↑↓・Home・End で移動、Esc でボタンへ戻って閉じる。外を押すと、下にあるものを押さずに閉じる。一覧のスクロールでボタンが見えなくなったら閉じる |
| REQ-LST-014 | 画面が変わる操作（カードを開く・メニュー）をマウスで押したとき、続けて押した分（ダブルクリックの2回目）を1秒だけ捨て、変わった後の画面のものを押さない |
| REQ-LST-015 | 最後のバックアップから7日以上たっている、またはこの端末でバックアップした記録がないときは、注意（エラーではない）として「バックアップへ」のボタン付きで知らせる |
| REQ-LST-016 | 一覧は「各請求書の現在の保存内容」で、保存版ごとの履歴ではないことを示す |

## 受け入れ基準

| ID | 前提 | 操作 | 結果 |
|---|---|---|---|
| AC-LST-001 | 請求書が21件 | 一覧を開く | 新しい20件が出て「次の20件」で21件目が出る |
| AC-LST-002 | タイトル「A工務店」と上部欄「B商事」の請求書 | 「B商」で絞り込む | 上部欄で一致した請求書だけが出る |
| AC-LST-003 | 最後に出力した後に編集・保存した請求書 | 一覧を見る | 「出力可」になる（「出力済み」ではない） |
| AC-LST-004 | 請求書 X を複製した請求書 Y | X を削除する | Y は残り、「複製」の表示が消える。Y の内容・保存版・更新日時は変わらない |
| AC-LST-005 | 開いている請求書を一覧から削除 | — | 編集の状態が閉じ、Ctrl+S などで削除した請求書が保存し直されない |
| AC-LST-006 | 3件を選んでいる | カードをマウスで押す | 開かずに、そのカードの選択が切り替わる |
| AC-LST-007 | 削除の応答が届かない | 削除する | 「削除の結果を確認できませんでした。…」が出て、一覧を読み直す |

## 未確定・既知の問題

- E-09（`audit/`）: 「新規請求書」「複製して編集」を押しただけで保存され、空の下書きが溜まる。推奨は「最初の編集まで保存しない」（未決定。削除で手動で消せるようにした）。
- E-10: 絞り込みが全角・半角を区別する（材料検索と規則が違う）。
- T-03: 表示倍率125%の Windows で `invoice-delete.spec.ts` の1件が失敗する（テストの問題）。

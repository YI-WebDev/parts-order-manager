# F11 起動・画面全体・終了

アプリの起動、画面の切り替え、全体のショートカット、通知、終了確認、二重起動の防止、異常時の動き。構成は [02-architecture.md](../02-architecture.md)。

- 画面: `App.tsx`、`ErrorBoundary.tsx`、`main.tsx`、`tauri-api.ts`
- 本体: `src-tauri/src/lib.rs`・`host.rs`・`instance.rs`・`paths.rs`・`win.rs`
- IPC: `app:info`・`window:close`・`documents:close`、イベント `documents:close-requested`

## 画面の構成

| タブ | 画面 | 仕様 |
|---|---|---|
| 請求書 | 請求書一覧 → 請求書の編集 | [F05](F05-invoice-list.md)・[F06](F06-invoice-editor.md) |
| 材料 | 材料台帳・取込履歴 → Excelから取込 | [F04](F04-material-ledger.md)・[F01](F01-material-import.md)・[F02](F02-material-reimport.md) |
| 設定 | バックアップと復元、アプリ情報（バージョン・データの保存場所・復元の回復結果） | [F10](F10-backup-restore.md) |

ヘッダーには、アプリ名・タブ・「材料を検索…」（Ctrl+F）を出す。

## 要件

| ID | 要件 |
|---|---|
| REQ-APP-001 | 起動時は「請求書」タブの請求書一覧を出す |
| REQ-APP-002 | タブの移動・請求書を開く・新規作成などの画面の切り替えは、未保存の確認（[F06](F06-invoice-editor.md) の REQ-EDT-301）を通す |
| REQ-APP-003 | 処理中（保存・出力・削除・取込・材料の編集など）は、タブ・「材料を検索…」・ショートカットを止める |
| REQ-APP-004 | 全体のショートカット: Ctrl+F（材料検索パレットを開く）、Ctrl+S（請求書を開いていれば今すぐ保存）、Ctrl+N（新規請求書。文字の入力欄では受け付けない。請求書一覧の選択のチェックでは受け付ける。材料検索パレットを開いている間は受け付けない）。Alt・Meta と一緒のとき、変換中、処理中は受け付けない |
| REQ-APP-005 | 通知（トースト）は画面の下に出し、8秒で消す（「…」で終わる処理中の通知は、結果が出るまで消さない）。「閉じる」で消せる。編集画面では下の操作の帯の上に出す |
| REQ-APP-006 | 処理の失敗は画面上部に `role="alert"` で出す。想定外の失敗は「操作を完了できませんでした。編集中の内容は保持しています。」 |
| REQ-APP-007 | 「設定」のアプリ情報は `app:info` から取り、取れなければ「再試行」を出す。保存場所が同期フォルダーやネットワーク上にないことを確かめるよう案内する |
| REQ-APP-008 | 画面の `window.close()` は、ウィンドウの「閉じる」と同じく終了確認へ進む |

## 終了確認

| ID | 要件 |
|---|---|
| REQ-APP-101 | ウィンドウを閉じようとしたら、本体はすぐには閉じず、確認用のトークンを付けて画面に終了確認を求める（同じ終了確認の間はトークンを使い回す） |
| REQ-APP-102 | 画面は未保存の確認（保存して続ける・破棄・戻る）を通し、閉じてよければ `documents:close(token)` を返す。本体はトークンが一致したときだけ閉じる（違えば「終了確認が一致しません。」） |
| REQ-APP-103 | 編集画面の欄で変換中なら閉じず、「日本語の変換を確定してから、もう一度閉じてください。」を出す |
| REQ-APP-104 | 取込の処理中・更新取込の確認中・材料のドロワーを開いている間は、終了の求めに応じない（何も表示しない。`audit/` の I-02） |
| REQ-APP-105 | 画面が応答しないときは、本体が「画面が応答していません。」で「待つ」「強制終了」を確かめる。強制終了なら保存前の入力を捨てて閉じる |
| REQ-APP-106 | 画面のプロセスが止まったら「画面が停止しました」を出してから終了する |
| REQ-APP-107 | 画面の描画で例外が起きたら、「画面でエラーが発生しました」と、保存済みの内容は保持されていること・最後の自動保存より後の入力は失われている可能性を示し、「アプリを終了」を出す。この画面でも終了確認に応じて閉じられる |

### 終了確認の状態

| 今 | 出来事 | 次 |
|---|---|---|
| 通常 | ウィンドウの「閉じる」 | 確認中（トークン発行、画面へ通知） |
| 確認中 | 画面が `documents:close(正しいトークン)` | 閉じている（`closing`。次の「閉じる」はそのまま閉じる） |
| 確認中 | 画面が未保存の確認で「戻る」 | 確認中のまま（次の「閉じる」は同じトークンで通知） |
| 確認中 | 誤ったトークン | 確認中のまま（エラー） |
| 任意 | 応答なしで「強制終了」・画面の停止・復元の完了 | 閉じている |

## 起動と二重起動

| ID | 要件 |
|---|---|
| REQ-APP-201 | 保存場所は [02-architecture.md](../02-architecture.md) の「保存場所」のとおり決める。決められなければ「保存場所（AppData）を確認できません。」などを出して終わる |
| REQ-APP-202 | 同じ保存場所で起動中なら、起動中のウィンドウを（最小化を解いて）前面に出し、2つ目は何も出さずに終わる。保存場所が違えば同時に起動できる |
| REQ-APP-203 | 中断した復元を回復してから DB を開く。DB を開けない（版が新しい・履歴が違う・整合性がない・移行の前の複製に失敗）ときは、理由を出して起動しない |
| REQ-APP-204 | 画面を表示できない（WebView2 がない）ときは「画面を表示できませんでした。Microsoft Edge WebView2 ランタイムが入っているか確認してください。」を出す |
| REQ-APP-205 | 想定外の内部エラー（パニック）では、「予期しないエラーのため、アプリを終了します。保存済みの内容は保持されています。…」を出してから終わる |
| REQ-APP-206 | 最小化している間は WebView2 のメモリ使用を抑える |

## 受け入れ基準

| ID | 前提 | 操作 | 結果 |
|---|---|---|---|
| AC-APP-001 | 未保存の変更がある | ウィンドウの×→「保存して続ける」 | 保存してから閉じる |
| AC-APP-002 | 未保存の変更がある | ウィンドウの×→「戻る」→もう一度× | 同じ確認がもう一度出る |
| AC-APP-003 | 起動中 | 同じ保存場所でもう一度起動する | 2つ目は開かず、1つ目が前面に出る |
| AC-APP-004 | 請求書の品名の欄で変換中 | ウィンドウの× | 閉じず、確定を求める |
| AC-APP-005 | 画面の描画で例外 | 「アプリを終了」 | 終了確認を経て閉じる |
| AC-APP-006（想定外の操作） | 請求書一覧の検索欄にフォーカス | Ctrl+N | 新規請求書を作らない |

## 未確定・既知の問題

`audit/` の未対応の指摘: E-11（終了確認の受け取りを再描画のたびに付け直しており、「閉じる」を取りこぼしうる）、I-02（取込の確認中などは×が黙って無視される。推奨は通常の終了確認へ進めること）、B-09（保存場所がジャンクションだと起動できない）、B-12（起動の失敗を表示している間の再起動）。Windows の二重起動・前面表示は自動テストがない（[08-traceability.md](../08-traceability.md)）。
